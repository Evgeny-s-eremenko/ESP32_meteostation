# Безопасный план: физическая кривая солнца и расширенный виджет

## Цель

Реализовать последний согласованный вариант виджета солнца:

- физически обоснованная кривая высоты Солнца вместо искусственной суточной синусоиды;
- единая плавная кривая на всём диапазоне суток;
- сохранение полного нисходящего участка до конца суток;
- комбинированное масштабирование: увеличить высоту canvas и уменьшить вертикальную амплитуду;
- desktop canvas примерно `175 px` вместо `150 px`;
- mobile canvas примерно `120 px` вместо `100 px`;
- вертикальный диапазон отображения примерно `110°` вместо `90°`;
- сохранение временной и вертикальной frontend-калибровки.

План предназначен для будущих сессий и других моделей. Главный приоритет — не потерять доступ к OTA и не нарушить стабильность станции.

## Текущая базовая конфигурация

- Исходники после ручного отката не содержат изменений OTA, расширенного `/ws1` или физической кривой.
- `src/web/ota.cpp` содержит исходную OTA-логику.
- `src/web/server.cpp` содержит исходную регистрацию OTA callback, включая `server.onFileUpload(handleUpdateUpload)`.
- `/ws1` передаёт только исходные поля:
  - `nowTime`;
  - `sunriseTime`;
  - `sunsetTime`;
  - `sunElevation`;
  - `solarNoon`.
- `data/sunset.js` использует исходную кусочную модель синусоиды.
- Пользователь восстановил станцию прошивкой и LittleFS через кабель; после полной прошивки станция работает стабильно, а OTA снова доступен.
- В `AGENTS.md` зафиксировано: таймаут MCP OTA является неопределённым результатом; после него необходимо дождаться станции и проверить применённое содержимое через Playwright, не повторяя загрузку сразу.

## Подводные камни, выявленные в предыдущих сессиях

### Несовместимость firmware и LittleFS

Нельзя загружать новый `sunset.js`, который требует новых полей `/ws1`, вместе со старой прошивкой. Нельзя также загружать новую прошивку с frontend, который ожидает ещё не существующие поля.

Каждая версия должна иметь совместимый комплект:

```text
firmware.bin + littlefs.bin
```

Перед любой загрузкой необходимо определить, какая версия сейчас установлена, и проверять совместимость полей `/ws1`.

### Риск повреждения LittleFS через OTA

Ранее были зафиксированы:

- `����` вместо HTML;
- зависание главной страницы;
- `TypeError: Failed to fetch`;
- таймауты и разрывы OTA;
- ухудшение ping после открытия веб-интерфейса.

Поэтому нельзя считать ответ OTA MCP достаточным подтверждением. После каждого таймаута нужно проверять:

- доступность ESP32;
- HTTP-код `/index.html`;
- `Content-Type`;
- начало HTML с `<!DOCTYPE html>`;
- отсутствие символов `�`;
- актуальность `sunset.js`.

### Не менять OTA в рамках виджета

Реализация виджета не должна изменять:

- `src/web/ota.cpp`;
- регистрацию `/update`;
- `src/web/server.cpp` вокруг OTA;
- формат OTA-загрузки;
- механизм перезагрузки.

Если OTA-исправление потребуется отдельно, оно должно иметь собственный план, отдельную сборку, тестирование и явное согласование.

### Не считать `Failed to fetch` доказательством провала

При успешном OTA ESP32 может перезагрузиться до того, как браузер получит финальный HTTP-ответ. Поэтому `Failed to fetch` может означать штатный reboot.

Но нельзя автоматически считать такую загрузку успешной. Нужно подтвердить результат повторным открытием станции и проверкой содержимого.

### Риск нагрузки от WebSocket

Физическая модель не должна создавать новые таймеры или новые WebSocket-соединения. Один экземпляр `sunset.js` должен создавать только одно соединение `/ws1` и один интервал запросов.

Проверить размер буфера для расширенного `/ws1`. Не ограничивает ли текущий буфер максимально возможные значения расширенного `/ws1`?

Нельзя добавлять бесконечный reconnect-loop без ограничителя и проверки состояния сокета.

## Архитектура реализации

### Физические параметры

Для полноценного расчёта высоты Солнца frontend должен получать совместимый набор параметров:

- `latitude`;
- `solarDeclination`;
- `stationSeconds`;
- существующие `solarNoon`, `sunElevation`, `sunriseTime`, `sunsetTime`.

Если эти поля отсутствуют в текущей прошивке, есть два безопасных варианта:

1. отложить физическую модель и сначала подготовить совместимый комплект firmware + LittleFS;
2. отдельным согласованным изменением расширить `/ws1`, сохранив все старые поля и добавив версию протокола.

Нельзя незаметно менять формат `/ws1` только на одной стороне.

### Формула

Использовать:

```text
hourAngle = (stationSeconds - solarNoon) * 15° / 3600

sinElevation =
    sin(latitude) * sin(declination) +
    cos(latitude) * cos(declination) * cos(hourAngle)

elevation = asin(clamp(sinElevation, -1, 1))
```

Преобразование в canvas должно быть линейным и единым для суток:

```text
y = horizonY - (elevation - visualHorizonElevation) * pixelsPerDegree
```

Для начальной калибровки использовать:

- `visualHorizonElevation = -0.833°`;
- диапазон `visualElevationRange = 110°`;
- `pixelsPerDegree = canvasHeight / visualElevationRange`.

Не использовать `smoothstep`, отдельные day/night amplitude и кусочные ветви.

### Калибровки

Сохранить frontend-only параметры:

const visualSunriseOffsetSec = 0;
const visualSunsetOffsetSec = 0;
const visualHorizonOffset = 0;
```

Они не должны менять подписи или данные станции. Любая поправка должна влиять только на presentation layer.

## Порядок реализации

1. Зафиксировать baseline до изменения:
   - `git status`;
   - хеши текущих `firmware.bin` и `littlefs.bin`, если доступны;
   - `pio run -e esp32dev` и `buildfs` без изменений;
   - read-only диагностика станции через MCP;
   - HTTP/Playwright-проверка `/`, `/index.html`, `/sunset.js`;
   - количество полей `/ws1`.
2. Подготовить локальную физическую модель в отдельном frontend-изменении, но не загружать её на станцию.
3. Если нужны новые поля `/ws1`, внести минимальные изменения в firmware:
   - добавить поля с новыми именами;
   - увеличить JSON-буфер с запасом;
   - не менять старые поля;
   - не менять OTA, задачи, NVS и протоколы;
   - добавить `apiVersion` только при необходимости и совместимым образом.
4. Собрать firmware для `esp32dev` и `esp32s3`, затем LittleFS для обеих платформ. Остановиться при любой ошибке сборки и исправлять локально, не трогая станцию.
5. Проверить образы локально:
   - наличие файлов;
   - размер;
   - перечень `mklittlefs` для LittleFS;
   - наличие `index.html`, `sunset.js`, `script.js`;
   - `node --check data/sunset.js`.
6. Выполнить browser-only проверку собранного frontend через локальный тестовый сервер или статический preview. Проверить desktop/mobile и отсутствие ошибок консоли.
7. Перед OTA получить read-only состояние станции. Если станция работает нестабильно, не начинать OTA.
8. Для совместимого комплекта сначала определить порядок загрузки по состоянию станции. Если firmware уже умеет обслуживать текущий LittleFS, предпочтительно загрузить LittleFS и проверить его. Если frontend требует новых `/ws1`, сначала требуется совместимая firmware, но только после подтверждения доступности OTA.
9. После каждой OTA-загрузки:
   - не повторять загрузку сразу при таймауте;
   - дождаться станции;
   - проверить uptime, IP и heap через MCP;
   - проверить `/index.html`, `/sunset.js`, HTTP-заголовки и UTF-8 через Playwright;
   - только после подтверждения переходить к следующему образу.
10. После применения совместимого комплекта проверить страницу минимум 30 секунд:
    - console errors;
    - network failures;
    - `/graph-data` раз в 5 секунд;
    - одно `/ws1` соединение;
    - отсутствие зависания;
    - отсутствие ухудшения ping по сравнению с baseline.
11. Проверить положение кривой ближе к полуночи. Если ветвь всё ещё обрезается, выполнить только frontend-итерацию с изменением `visualElevationRange` или высоты canvas. Не менять firmware и OTA.
12. После каждой frontend-итерации повторить локальную сборку LittleFS и Playwright-проверку. Не загружать более двух вариантов без фиксации результатов и согласования.

## Проверки виджета

### Desktop

- `#sunCanvas` и контейнер: `175 px` по высоте;
- кривая физически непрерывна;
- в 21:00–23:00 кривая не касается нижней границы преждевременно;
- горизонталь и заливка не выходят за canvas.

### Mobile

- `#sunCanvas` и контейнер: `120 px` по высоте;
- нижняя часть не обрезается;
- подписи восхода/заката и дата не перекрываются;
- форма не зависит от `devicePixelRatio`.

### Физическая согласованность

- расчёт frontend в текущий момент совпадает с серверным `sunElevation`;
- `stationSeconds` используется вместо локального времени компьютера;
- солнечный полдень находится в максимуме дневной части;
- исходные подписи и длительность дня не изменяются.

## Безопасность и необратимые действия

Запрещено в рамках этого плана:

- прошивать через USB без отдельного запроса пользователя;
- разбирать станцию;
- менять partition table;
- выполнять factory reset/NVS reset;
- удалять или форматировать LittleFS отдельной командой на устройстве;
- загружать firmware, если доступность OTA не проверена;
- повторять OTA автоматически после таймаута;
- менять OTA-обработчик ради реализации виджета;
- выполнять более двух попыток на одном этапе без запроса пользователя;
- считать timeout или `Failed to fetch` окончательным результатом без проверки станции.

При двух неудачах на любом этапе остановиться и запросить дальнейшие действия пользователя.

## Критерии завершения

Работа считается завершённой только если:

- исходники собираются для затронутых окружений;
- LittleFS-образ локально проверен;
- firmware и LittleFS совместимы по `/ws1`;
- страница открывается без зависания;
- HTML не повреждён и не содержит `�`;
- консоль браузера не содержит повторяющихся ошибок;
- ping и потери пакетов не ухудшились относительно baseline;
- физическая кривая полностью видна до конца суток;
- подтверждены desktop и mobile;
- результат OTA подтверждён содержимым после reboot, а не только ответом MCP.
